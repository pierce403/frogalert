# FrogAlert 0.3.0-beta.1

This release moves the FrogAlert application into allocation-free Rust and adds
a deterministic emulator using the same code that runs on the badge.

- One state machine owns scan timing, alert pages, cancellation, and shutdown
  handoff. Lost callbacks cannot enable advertising or power down an active
  scan. Shutdown also waits for advertising and an app connection to stop.
- Completed counts stay steady, report deduplication includes address type,
  and ephemeral addresses are wiped on completion, cancellation, or timeout.
- Detection validates complete advertisement packets before matching. CRC and
  exact-profile checks protect the existing bounded configuration format.
- Rust renders alerts, count/frog views, animation crops, and boot/battery
  cards. Upload validation handles padded packets, interrupted transfers,
  bounded allocation, flash errors, and invalid calendar fields.
- The SDK emulator covers both board profiles and both views, wrapping clocks,
  failures, lost/late callbacks, connection races, and a 24-hour soak per
  configuration. C conformance tests exercise the actual Rust ABI and generated
  upload receiver, including allocation and flash-write failures.

The proven FOSSASIA/WCH C shell still owns startup, vectors, USB/BLE drivers,
display interrupts, allocation/flash, nametag storage, physical buttons, and
ROM ISP. Rust does not replace those hardware boundaries. Both exact USB-C
profiles retain their existing physical button roles and button-only wake.

The standard top/bottom pair is published from audited, attested CI output.
These new bytes are **hardware-unverified**: emulation and structural audits do
not establish RF reliability, current draw, physical button timing, USB/app
compatibility, or recovery on a badge. Historical standalone Rust images
remain quarantined. The optional dancing-frog lane is build evidence only.
