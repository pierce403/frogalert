# FrogAlert 0.2.0-beta.15

This release restores beta.12's low-power CH582 hardware shutdown after the
owner determined that beta.12's Android BadgeMagic upload failure was most
likely environmental Bluetooth congestion rather than a firmware regression.
Screen off waits for passive discovery to become idle, stops the display and
button timers, and enters hardware shutdown. Exact-profile wake handling still
preserves the continuously held KEY2 path into mask-ROM ISP.

The inherited BadgeMagic `FEE0`/`FEE1` receive path is also hardened without
changing the Android protocol. The accepted connection now receives the
upstream-intended connection-parameter request with a six-second supervision
timeout. The receiver reserves the app's complete padded 16-byte final packet,
bounds declared content below FrogAlert's configuration block, rejects nonzero
ATT offsets, checks the Data-Flash result, resets partial state on disconnect,
and no longer dumps every received byte through the debug channel.

FOSSASIA's current Android app sends 16-byte writes with responses, spaces them
by 120 ms, and retries failed writes. These firmware changes preserve that
contract. They are source- and CI-audited, not a physical proof: both exact PCB
profiles still require upload, disconnect/retry, screen-off current, wake, and
KEY2 recovery tests.
