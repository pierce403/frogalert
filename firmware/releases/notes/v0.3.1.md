# FrogAlert 0.3.1

Repair likely causes of reduced BLE survey counts following the Rust rewrite.

- Correct a confirmed SDK adapter bug: TMOS timer success returns Boolean 1,
  not status 0. Successful timers no longer create immediate wake loops.
- Reuse the scheduled timer instead of stopping and allocating it per report.
  Retry allocation failure on the existing 200 ms recovery-button cadence.
- Read controller state once per report and reuse rendered frames until a
  deadline, view change, or higher-priority alert requires an update.
- Preserve active scan results across transient INIT/ERROR peripheral states.
  New scans and shutdown still require readable idle state; actual connections,
  unknown states, and failed state reads continue to cancel scanning.
- Reapply and verify the original scan settings and 64-result capacity before
  each discovery, including after role startup retries.
- Execute the production C survey adapter with the real Rust library and
  pinned WCH headers in the emulation suite. Cover scheduler failure, bursts,
  completion lists, state transitions, synchronous callbacks and clock wrap.

Passive three-second surveys about every twenty seconds, power handling,
button roles, and KEY2 ROM-ISP recovery are retained. The scheduler defect is
reproduced in host tests; restored physical RF counts still need confirmation
on the new images. Releases remain CI-audited with truthful hardware status.
